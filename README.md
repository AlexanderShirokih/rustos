# RustOS Mobile

Экспериментальная операционная система для AArch64 с capability-based
микроядром на Rust. Проект включает собственные загрузчик, планировщик,
IPC, управление памятью и capability-систему, а также userspace-сервисы,
драйверы и порт стандартной библиотеки Rust.

## Идея

Микроядро предоставляет механизмы, на которых строится система: изоляцию
процессов, управление памятью, планирование потоков, IPC и контроль доступа.
Драйверы и файловые системы работают в отдельных userspace-процессах.
Сервисы общаются через IPC и могут передавать друг другу доступ к разделяемой
памяти.

Процесс получает доступ к ресурсам через capability — хендлы на объекты
ядра с заданными правами. Например, драйверу выдаются окно регистров и линия
прерывания его устройства, а клиенту файлового сервера — сессия для файловых
операций. Держатель capability может выдать производную с ограниченными
правами и позднее отозвать её вместе с производными, в том числе в других
процессах. Передача через IPC сохраняет права; дублирование позволяет их сузить.

Состав системы задают манифесты программ и план загрузки. Компонент объявляет
свои требования и предоставляемые сервисы, а rootkeeper связывает их,
запускает нужные процессы и управляет перезапусками. Провайдер сервиса может
запускаться по запросу клиента.

Платформенный слой ядра отвечает за загрузку, MMU, прерывания и переключение
контекста. Общие механизмы ядра используют интерфейс HAL.

## Возможности

- Изолированные процессы и потоки, приоритетное вытесняющее планирование,
  работа на нескольких ядрах процессора.
- Capability с правами доступа: дублирование с равными или меньшими правами,
  передача между процессами и каскадный отзыв производных.
- Управление физической и виртуальной памятью: отдельные бюджеты процессов,
  разделяемые регионы и окна памяти устройств.
- Синхронные порты для сообщений и запросов с ответом, типизированные
  IPC-контракты. Сообщения передают данные и capability; разделяемая память
  позволяет процессам обращаться к общим данным.
- Состав userland-образа и план загрузки в TOML. Rootkeeper запускает
  компоненты, связывает их требования с экспортами и перезапускает процессы
  по заданной политике. Образ собирается через `cargo xtask`.
- Файловая подсистема с маршрутизатором путей, деревом файлов образа только
  для чтения и изменяемой файловой системой в памяти. После разрешения пути
  клиент общается с файловым сервером напрямую. Сессия с корнем на подкаталоге
  позволяет предоставить доступ к части дерева.
- Userspace-драйверы часов PL031, фреймбуфера simplefb и шины virtio-mmio.
  Доступ к регистрам и линиям прерываний выдаётся через capability.
- Стандартная библиотека Rust: обычный `fn main`, потоки, синхронизация,
  файловые операции и системный журнал.
- Автоматические проверки на хосте и под QEMU, включая тесты userspace
  на рабочем ядре.

UEFI-загрузка, сетевой стек и дисковая файловая система пока не реализованы.
Поддерживаемые операции файловой подсистемы описаны в
[docs/filesystem.md](docs/filesystem.md).

## Программы

Пользовательская программа пишется на обычном Rust: `fn main`, `println!`,
контейнеры из `std`, потоки и файловые операции. Минимальный пример:

```rust
fn main() {
    println!("hello");
}
```

Вывод поступает в системный журнал под именем компонента. Системные операции
доступны через `std::os::molecular`, а требования к сервисам объявляются
в манифесте компонента.

Примеры в репозитории:

- [hello-std](user/examples/hello-std/src/main.rs) — программа на стандартной
  библиотеке с выводом в журнал;
- [clock-std](user/examples/clock-std/src/main.rs) — получение времени через
  сервис часов;
- [files-demo](user/examples/files-demo/src/main.rs) — работа с файловой
  подсистемой: чтение файла образа, запись в ramfs и обход каталога.

Драйверы и системные сервисы могут использовать `no_std` и рантайм проекта.
Устройство образа и создание компонента описаны в
[docs/userland.md](docs/userland.md).

## Платформы

Репозиторий содержит конфигурации для
[QEMU AArch64](devices/spec/qemu-aarch64.yaml),
[Raspberry Pi 5](devices/spec/rpi5.yaml) и
[Xiaomi Redmi Note 7](devices/spec/xiaomi-lavender.yaml) (Qualcomm SDM660).
Конфигурация задаёт формат загрузочного образа, параметры загрузки и команду
запуска. Для телефона собирается Android boot image, загружаемый через fastboot.
