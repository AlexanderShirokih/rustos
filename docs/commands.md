# Команды

## Быстрая справка

| Действие                            | Команда                                                                                                              |
|-------------------------------------|----------------------------------------------------------------------------------------------------------------------|
| Основные проверки одной командой    | `cargo xtask check [--all] [--only <name>] [--list] [--fail-fast]`                                                    |
| Host-тесты по всем workspace        | `cargo xtask test`                                                                                                   |
| Clippy по всем workspace            | `cargo xtask clippy [--host] [--target] [--arch <name>]`                                                             |
| Cargo в workspace userspace         | `cargo xtask userland <аргументы cargo>`                                                                             |
| Форматирование                      | `cargo xtask fmt [--check]`                                                                                          |
| Документация по всем workspace      | `cargo xtask doc`                                                                                                     |
| Исходники `std` с оверлеем          | `cargo xtask std-src [--force] [--verify [--arch <name>]]`                                                           |
| Проверка слоёв                      | `cargo xtask check-layers`                                                                                           |
| Проверка кодстайла                  | `cargo xtask style [--all] [--staged] [--since <rev>] [--base <rev>]`                                                |
| Поиск дублирующегося кода           | `cargo xtask similarity [--write-baseline] [--no-baseline] [--base <rev>]`                                           |
| Сборка userland                     | `cargo xtask build-userland [--image <путь>] [--arch <name>] [--file <путь>=<источник>]`                                          |
| Загрузочный образ (userland + ядро) | `cargo xtask build devices/spec/<device>.yaml [--image <путь>] [--file <путь>=<источник>]`                           |
| Запуск после сборки                 | `cargo xtask build devices/spec/<device>.yaml --run`                                                                 |
| QEMU integration tests              | `cargo xtask qemu-test [--timeout <сек>] [--spec <путь>]`                                                            |
| Userspace stress в QEMU             | `cargo xtask stress [--seed <n>] [--seeds <n>] [--steps <n>] [--epoch <n>] [--shard <n>] [--shards <n>] [--timeout <сек>]` |
| Замеры файловых плоскостей в QEMU   | `cargo xtask bench [--timeout <сек>]`                                                                                |
| Host race под ThreadSanitizer       | `cargo xtask race`                                                                                                    |
| Ограниченный fuzz-прогон            | `cargo xtask fuzz <target> [--seconds <сек>]`                                                                         |

Отделённые workspace в `--workspace` не входят. По всем workspace идут
`cargo xtask fmt`, `cargo xtask clippy`, `cargo xtask doc` и `cargo xtask test`
([«Clippy и тесты по профилю»](#clippy-и-тесты-по-профилю)).

Отдельные команды таблицы нужны, когда проверяется одна вещь. Дифф целиком
проходит через [`cargo xtask check`](#основные-проверки).

## Основные проверки

```
cargo xtask check [--all] [--only <name>] [--list] [--fail-fast]
```

Прогоняет по рабочему дереву весь основной инструментарий: форматирование,
линтеры, тесты, проверки слоёв, стиля и документации. Отдельные команды таблицы
остаются для случая, когда проверяется одна вещь. По умолчанию идут проверки,
которым хватает обычной сборки дерева.

Набор проверок, их команды и очереди задаёт `checks.toml` в корне дерева.

| Флаг            | Назначение                                                                                          |
|-----------------|------------------------------------------------------------------------------------------------------|
| `--all`         | Добавить проверки, требующие инструмента вне обычной сборки                                           |
| `--only <name>` | Запустить только названную проверку; повторяется по числу проверок                                    |
| `--list`        | Напечатать состав отобранного набора, ничего не запуская                                              |
| `--fail-fast`   | После первой неудачи не начинать новых проверок; по умолчанию прогон идёт до конца и сводит упавшие проверки в отчёт |

```bash
cargo xtask check --only style --only clippy-host
```

Каждая проверка стоит в очереди, которую называет её поле `lane`. Очереди идут
параллельно, а проверки внутри очереди — одна за другой. Очередей всего две.

В очереди `cargo` собраны те, что запускают cargo: `doc`, `clippy-host`,
`clippy-target`, `test`. Каталог сборки у них общий, и запусти их одновременно —
они всё равно выстроятся в очередь на его замке. В очереди `sources` — проверки,
которые только читают исходники: `fmt`, `check-layers`, `style`, `similarity`.

Пока в наборе больше одной очереди, вывод каждой проверки печатается целым блоком
по её окончании. Иначе строки соседних очередей шли бы по общему терминалу
вперемешку. Набор из одной очереди печатает вывод сразу, по ходу дела.

## Сборка

```
cargo xtask build <spec> [--run] [--debug] [--features <features>] [--image <путь>] [--file <путь>=<источник>]
```

Читает YAML-спеку устройства, собирает `target/build/userland.img`, затем
собирает пакет `hal-<arch>` под target архитектуры из поля `arch` спеки с
`--release` из workspace `kernel/platform` и упаковывает результат по правилам
`boot.format`. Программы образа идут под свой таргет, и стандартная библиотека
поднимается им из исходников, которые готовит `cargo xtask std-src`
([workspace.md](workspace.md#таргеты-сборки)).

| Флаг                       | Назначение                                                                                                                           |
|----------------------------|---------------------------------------------------------------------------------------------------------------------------------------|
| `--run`                    | После сборки выполнить команды из секции `run` YAML-спеки                                                                             |
| `--debug`                  | После сборки выполнить команды из секции `debug` YAML-спеки                                                                           |
| `--features <список>`      | Дополнительные features (через запятую)                                                                                              |
| `--image <путь>`           | Относительный путь к TOML-манифесту userland-образа. По умолчанию `user/system/rootkeeper/image.toml`                                 |
| `--file <путь>=<источник>` | Файлы образа поверх манифеста: путь записи и источник относительно корня проекта, подстановки включая. Повторяется по числу источников |

```bash
cargo xtask build devices/spec/xiaomi-lavender.yaml --image user/examples/calculator-demo/image.toml
```

Артефакты по формату загрузчика:

| `boot.format`     | Артефакт                                                                                      |
|-------------------|-----------------------------------------------------------------------------------------------|
| всегда            | `target/build/userland.img`                                                                   |
| `linux_arm64`     | `target/build/kernel.bin` + `target/build/userland.img` (initrd)                              |
| `android_boot_v1` | `target/build/boot.img` с `userland.img` в ramdisk (DTB конкатенирован с kernel.gz)           |
| `android_boot_v2` | `target/build/boot.img` с `userland.img` в ramdisk (DTB передаётся отдельным полем заголовка) |
| `uefi`            | не реализован                                                                                 |

## Userland

```
cargo xtask build-userland [--image <путь>] [--arch <name>] [--file <путь>=<источник>]
```

Собирает только `target/build/userland.img`. Флаги те же, что у `build`. Состав
манифеста описан в [userland.md](userland.md#образ).

```bash
cargo xtask build-userland --image user/testing/testrunner/image.toml
cargo xtask build-userland --file /boot/rootkeeper/motd=user/system/rootkeeper/motd.txt
```

## Тесты

Уровни тестов и выбор прохода для нового теста — в [testing.md](testing.md).

```bash
cargo xtask test
cargo xtask qemu-test [--timeout <сек>] [--spec <путь>]
```

По умолчанию тайм-аут — 60 секунд, спека — `devices/spec/qemu-aarch64-test.yaml`
с четырьмя CPU и GICv3. `--spec` меняет конфигурацию машины, оставляя проходы
прежними; `devices/spec/qemu-aarch64-test-gicv2.yaml` даёт ту же машину с GICv2,
покрывая второй бэкенд контроллера прерываний:

```bash
cargo xtask qemu-test --spec devices/spec/qemu-aarch64-test-gicv2.yaml
```

### Замеры

`bench` собирает образ testrunner с профилем `bench` и выбирает только
`#[kernel_test(bench)]`. Каждый замер печатает строку `[TEST-REPORT]` с видом
плоскости, размером операции и наносекундами на операцию.

```bash
cargo xtask bench
```

Прогон идёт под TCG, а там нет модели кеша и TLB. Отсюда и границы доверия к
числам. Зависимость цены операции от размера региона наблюдаема и переносима.
А вот абсолютная пропускная способность и соотношение цены IPC к цене
копирования переносимыми уже не будут.

### Stress, race и fuzz

`stress` собирает отдельный образ testrunner, выбирает только
`#[kernel_test(stress)]` и повторяет одну последовательность операций для
диапазона seed; каждый тест отчитывается за свой seed маркером `[STRESS-PASS]`.
Шаги одного seed разбиты на эпохи длиной `--epoch`, и каждая отчитывается
маркером `[STRESS-EPOCH]` со снятой на её границе величиной бюджета. Спеку
машины команда не выбирает и всегда идёт по умолчанию.

```bash
cargo xtask stress --seed 100 --seeds 32 --steps 256 --epoch 64 --timeout 900
```

`--shards` делит диапазон seed на равные части, `--shard` называет часть,
которую берёт прогон. Диапазон с остатком и номер за пределами числа шардов
команда отвергает до сборки образа.

```bash
cargo xtask stress --seeds 64 --steps 16384 --epoch 256 --shard 1 --shards 4
```

Один и тот же seed повторяет последовательность операций, но не их чередование.
Машина многопроцессорная, а порядок, в котором CPU входят в ядро, seed не задаёт.
Поэтому слой и проверяет границы жизненного цикла и ожиданий, а не конкретную
раскладку операций по времени. Ядро этого прохода собирается с фичей
`short-quantum`. Квант вытеснения становится 500 мкс вместо 10 мс, и чередований
на тех же шагах выходит заметно больше.

`race` запускает под ThreadSanitizer host-тесты гонок. Тест гонок — это
`#[test]`, имя которого начинается на `race_`. Состав прогона команда выводит из
дерева, беря пакеты корневого workspace, где такой тест есть. Найденные тесты
сверяются с отчитавшимися поимённо, и тест, не отчитавшийся о прохождении, даёт
отрицательный вердикт. Имя теста служит его тождеством, поэтому повторное имя в
дереве команда называет отказом. Тест в пакете, собираемом только под целевую
архитектуру, команда называет отказом тоже.

```bash
cargo xtask race
```

Fuzz-targets лежат в отделённом workspace `fuzz/`:

```bash
cargo xtask fuzz fdt_parse_walk --seconds 60
cargo xtask fuzz ipc_wire_decode --seconds 60
cargo xtask fuzz ramfs_ops --seconds 60
cargo xtask fuzz userland_image_decode --seconds 60
```

Корпус находится в `fuzz/corpus/<target>/`, crash-артефакты — в
`fuzz/artifacts/<target>/` и не добавляются в Git автоматически. Перед прогоном
`xtask` пересобирает затравки корпуса в `fuzz/seeds/<target>/` и передаёт
директорию вторым корпусом, доступным только на чтение. Для прямого запуска
доступны `cargo fuzz build --fuzz-dir fuzz` и `cargo fuzz run --fuzz-dir fuzz
<target> -- <libFuzzer args>`.

## Исходники `std` с оверлеем

```bash
cargo xtask std-src [--force] [--verify [--arch <name>]]
```

Копирует дерево `library` из компонента `rust-src` зафиксированного toolchain в
`target/std-src` и накладывает оверлей `patches/std-molecular.patch` — он
добавляет платформенный слой RustOS. Установленный toolchain при этом остаётся
нетронутым: sysroot общий, а копия принадлежит сборке. Повторный вызов пропускает
пересборку, пока не сменились ни оверлей, ни sysroot; `--force` пересоздаёт дерево
всегда.

Вторая половина подготовки — крейты дерева, которые собираются внутрь `std` и
объявляют фичу `rustc-dep-of-std`. Юниты графа `-Zbuild-std` cargo пересобирает по
смене зависимостей и флагов, но не по смене исходников. Оставь всё как есть — и
правка в `lib/runtime` молча уйдёт в собранный `std` старой версией. Поэтому такие
пакеты чистятся `cargo clean` по отпечатку их файлов.

`--verify` дополнительно собирает `hello-std` под системный таргет каждой записи
реестра архитектур; `--arch` сужает прогон до одной. Ловятся этим две вещи —
расхождение оверлея с пином из `rust-toolchain.toml`, из-за которого `git apply`
перестаёт ложиться, и поломка дерева, которое ложится, но не собирается. Проверка
дороже остальных — она поднимает из исходников `core`, `alloc` и саму стандартную
библиотеку, — и в CI поэтому идёт по собственному условию, по изменению того, из
чего собрана.

Команда печатает путь к дереву `library`; сборкой по нему распоряжается
`cargo xtask userland`.

## Clippy и тесты по профилю

```bash
cargo xtask clippy [--host] [--target] [--arch <name>]
cargo xtask doc
cargo xtask test
```

Команды обходят все workspace и запускают cargo в каждом по его профилю
([workspace.md](workspace.md#профили-сборки)); таргеты берутся из реестра
архитектур.

| Флаг            | Назначение                                                          |
|-----------------|---------------------------------------------------------------------|
| `--host`        | Только хостовая сторона: профили `common`, `host`, `fuzz`           |
| `--target`      | Только целевая сторона: каждая архитектура реестра                  |
| `--arch <name>` | Целевая сторона одной архитектуры; повторяется по числу архитектур   |

`cargo xtask test` гонит хостовые тесты профилей `common` и `host`. Остальные
профили проверяются под QEMU.

## Cargo в workspace userspace

Таргет и флаги сборки `std` workspace `user/` держит в `user/.cargo/config.toml`,
а путь к дереву исходников приходит переменной окружения. И то и другое ставит
`cargo xtask userland`: он материализует дерево и запускает cargo из каталога
workspace.

```bash
cargo xtask userland build --release --workspace
cargo xtask userland clippy --workspace --all-targets -- -D warnings
cargo xtask userland doc --no-deps --workspace
```

## Форматирование

```bash
cargo xtask fmt [--check]
```

Прогоняет rustfmt по корневому workspace и по каждому отделённому. `--check`
печатает файлы, которые расходятся с `rustfmt.toml`, и завершается с ошибкой,
ничего не переписав. Этот режим стоит в `hooks/pre-commit` и в CI.

Голый `cargo fmt --all` обрабатывает только членов своего workspace, и
отделённый до гейта не доходит.

## Проверка слоёв

```bash
cargo xtask check-layers
```

Сверяет рёбра зависимостей между крейтами корневого workspace и всех отделённых
(по `cargo metadata`) с правилами слоёв из [workspace.md](workspace.md#домены).
При нарушениях печатает запрещённые рёбра и завершается с ошибкой.

Каждая объявленная path-зависимость сверяется с исходниками пакета. Граф, по
которому идёт проверка слоёв, задаёт манифест, и ребро без единой ссылки в коде
этот граф искажает.

## Ссылки в документации

```bash
cargo xtask doc
```

Ссылка на переименованный или приватный элемент молча пропадает из документации.
Текст остаётся, а открыть его читателю уже негде. Флаг переводит такую ссылку в
ошибку вместе с прочими предупреждениями rustdoc.

## Проверка кодстайла

```bash
cargo xtask style [--all | --staged | --since <rev>]
                  [--write-baseline | --no-baseline] [--base <rev>]
                  [--format text|json] [--rule <id>]
```

Держит конвенции этого дерева, которые задаёт [`code-style.md`](code-style.md), —
doc-дисциплину, язык строковых литералов, формулировки и типографику текста.
Правила и уровни лежат в `style.toml`, а норму каждого сработавшего правила отчёт
печатает под списком находок.

По умолчанию сверяются строки, изменённые относительно `origin/main`. `--all`
берёт дерево целиком, `--staged` — индекс, этот режим и стоит в
`hooks/pre-commit`.

Накопленные нарушения приняты снапшотом `style-baseline.txt` и в отчёт не
попадают. `--write-baseline` пересобирает снапшот, `--no-baseline` печатает всё.

Пересобранный снапшот обязан стать короче. Выросший означает, что в него попало
нарушение нового кода, и чинить надо код, а не снапшот. Исключение одно — правило,
которого раньше в конфигурации не было. Его записи входят в снапшот целиком, и
рост по нему не в счёт.

`--base <rev>` завершает прогон отказом, если число принятых нарушений у правила
выросло. Этим режимом снапшот и проверяется в CI. Ревизию, для которой снапшот ещё
не записан, сверять не с чем.

Единичное исключение — директива с обязательным обоснованием:

```rust
// style:allow(doc_on_declaration) regression guard kept by owner request
```

Директива без обоснования, с неизвестным правилом или не покрывшая находок сама
становится находкой.

Коды возврата: `1` — осталась находка уровня `deny`, `2` — отказ инструмента.

## Поиск дублирующегося кода

```bash
cargo xtask similarity [--write-baseline | --no-baseline] [--base <rev>]
```

Сообщает пары функций одной формы. Версия анализатора `similarity-rs`,
разбираемые пути и пороги заданы в `similarity.toml`. Если анализатора нет или его
версия разошлась, команда скажет об этом вместе с командой установки.

Принятые пары держит `similarity-baseline.txt`. Пара вне записи завершает прогон
отказом. `--write-baseline` пересобирает запись, `--no-baseline` печатает и
принятые пары, а `--base <rev>` завершает прогон отказом, если число принятых пар
у файла выросло.

## Хук pre-commit

`hooks/pre-commit` гоняет перед коммитом обе проверки исходников:
[`cargo xtask fmt --check`](#форматирование) и `cargo xtask style --staged`. Git
берёт хуки из этой директории после

```bash
git config core.hooksPath hooks
```
