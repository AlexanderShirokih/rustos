# Rootkeeper

Rootkeeper — начальный userspace-процесс. Он читает план загрузки, запускает
компоненты и управляет их связями и перезапусками.

## План загрузки

План задаёт экземпляры программ, их бюджеты памяти и число перезапусков.
Источник плана — `system.toml`; сборщик проверяет его и размещает в
userland-образе. Требования и экспорты читаются из манифеста каждой
программы ([userland.md](userland.md#манифест-компонента)).

Пример:

```toml
version = 1

[[components]]
executable = "mounts"
memory_limit = "8M"
restarts = 2

[[components]]
executable = "filesystem-ramfs"
memory_limit = "4M"
```

| Ключ | Назначение |
|------|------------|
| `executable` | Идентичность программы: bin-таргет или `package::bin` |
| `name` | Имя экземпляра; по умолчанию — идентичность из `executable` |
| `memory_limit` | Предел памяти компонента |
| `restarts` | Число повторных запусков; по умолчанию ноль |

Одна программа может иметь несколько экземпляров с разными именами.
Имя используется для процесса и журнала. Экземпляры обращаются к одному
каталогу программы в образе.

`memory_limit` задаётся числом байт с двоичным суффиксом `K`, `M` или
`G` либо без суффикса. Предел округляется вверх до страницы. Из бюджета
компонента выделяются копируемые сегменты программы, куча и стеки.
Сегменты, отображённые из общих страниц образа, бюджет компонента не
расходуют. Загрузчик может разделять такие страницы для сегментов только
для чтения; остальные сегменты он копирует.
Условия разделения страниц заданы в
[userland-loader](../lib/userland-loader/src/image_pages.rs).

Повреждение образа или плана, отсутствие программы и нехватка ресурсов
останавливают загрузку композиции. Начальную программу ядро уже запустило;
rootkeeper повторно её не запускает.

## Связывание

Rootkeeper проверяет имя и протокол запрошенного требования по манифесту
компонента. Кандидаты — доступные экземпляры и программы из
[индекса экспортов](#индекс-экспортов), ещё не зарегистрированные как экземпляры.

Экспорт совпадает, когда все пары одного его фильтра присутствуют
в атрибутах запроса. Экспорт без фильтров совпадает с запросом без атрибутов.
Собственный экспорт компонента также участвует в поиске.

`session` открывает единственное совпадение. Отсутствие совпадений даёт
`Unbound`, неоднозначность — `Refused`.

Требование `all` позволяет перечислить подходящие экспорты или наблюдать за
их появлением. Перечисление фиксирует совпадения на момент запроса.
Наблюдение выдаёт каждый экспорт один раз, когда тот становится доступным,
и повторно после перезапуска провайдера.

Компонент выбирает экспорт и открывает сессию. Поиск не запускает провайдера;
запуск происходит при открытии сессии. Если после поиска провайдер снят
навсегда, открытие даёт `Unavailable`.

### Признаки машины

Компоненты плана могут получить сессию `Features` и публиковать признаки.
Признак действует до конца запуска опубликовавшего его компонента. Закрытие
сессии `Features` завершает публикацию этого запуска.

Пока компонент плана с требованием `Features` не завершил публикацию,
rootkeeper не запускает записи без этого требования. Перезапуск такого
компонента снова откладывает их запуск.

Программы индекса могут требовать признаки. Их экспорты становятся доступны,
когда опубликованы все требования. Запрос `session` к экспорту, скрытому из-за
признаков, получает `Unbound`. Программы с такими требованиями не включаются в
начальный план.

### Запуск по запросу

При первом открытии экспорта программы из индекса rootkeeper регистрирует
её и запускает процесс. Последующие заявки направляются этому экземпляру.
Нехватка ресурсов даёт `NoSpace`, прочие отказы регистрации — `Refused`.

Заявка на экспорт ждёт запроса `accept` от провайдера. Провайдер получает
заявку с атрибутами запроса импортёра и сам выдаёт импортёру сессию
([userland.md](userland.md#обслуживание-экспорта)).
Заявки сохраняются при перезапуске провайдера; снятие экземпляра навсегда
завершает их с `Unavailable`.

### Корневые сервисы

Корневые сервисы rootkeeper предоставляют системные ресурсы компонентам:

| Протокол | Назначение |
|----------|------------|
| `Hardware` | Доступ к устройствам через полномочия ядра |
| `SystemInfo` | Сведения о CPU и физической памяти |
| `Image` | Регион userland-образа |
| `Features` | Публикация признаков компонентами плана |
| `Journal` | Подписка на строки системного журнала |

Подписчик `Journal` получает последние сохранённые строки и последующие
записи через кольцо в разделяемой памяти. Медленный читатель пропускает
строки; запись о пропуске сообщает их число. Контракт определён в
[log-abi](../lib/log-abi/src/journal_session.rs).

Выданные сессии и производные capability отзываются при завершении
получившего их запуска.

## Провижининг устройств

Компонент `platform` получает `Hardware`, разбирает описание платформы и
публикует совместимости доступных устройств как признаки машины.

Драйвер получает сессию `Platform`, читает описание, выбирает устройство
и запрашивает ресурсы по его `DeviceId` и номеру ресурса. `platform`
разрешает линии прерываний и окна регистров по описанию платформы.

Линия и регион закрепляются за взявшей их сессией; другая сессия получает
отказ. Описание доступно всем сессиям только для чтения.
Закрытие сессии отзывает выданные ей описание, линии и регионы.

## Incarnation и перезапуск

Incarnation — один запуск экземпляра. Перезапуск создаёт новый процесс
с тем же именем. Выдачи прежнего запуска отзываются, новый процесс
запрашивает требования заново.

Ненулевой код выхода или закрытие стартовой сессии живым процессом
может привести к перезапуску. При закрытии сессии rootkeeper сначала
завершает процесс. Число повторных запусков ограничено `restarts`.

Нулевой код выхода, отказ запуска, невозвращённый бюджет или исчерпание
перезапусков снимают экземпляр навсегда. Rootkeeper пишет в журнал
имя экземпляра и причину завершения.

## Резерв бюджета

Перед первым запуском rootkeeper резервирует бюджет экземпляра.
При перезапуске резерв сохраняется. Новый процесс запускается после возврата
всего бюджета прежнего; ожидание возврата ограничено.
Невозврат бюджета прекращает перезапуски.

Правила учёта и возврата памяти определены в
[syscalls.md](syscalls.md#memory).

## Индекс экспортов

Сборщик формирует индекс из манифестов программ образа. Он позволяет
rootkeeper находить провайдеров, не включённых в начальный план.

Формат плана и индекса определяют
[lib/userland-image/src/plan.rs](../lib/userland-image/src/plan.rs) и
[lib/userland-image/src/exports.rs](../lib/userland-image/src/exports.rs).
Исходный план основного образа —
[user/system/rootkeeper/system.toml](../user/system/rootkeeper/system.toml).
