# Rootkeeper

`rootkeeper` — это корневой процесс, с которого начинается загрузка всей
userspace-подсистемы. `rootkeeper` владеет запуском и жизненным циклом системных
компонентов.

Rootkeeper поднимает userland по записи плана. Запись называет для каждого
компонента каталог программы, предел памяти, число перезапусков и провайдера
каждого требования `session`.

## План загрузки

План — отдельная запись userland-образа `/rootkeeper/plan`. Манифест образа
отвечает на вопрос, что лежит в образе; план — на вопрос, что и с какими
аргументами rootkeeper поднимает ([userland.md](userland.md#образ)).

Источник плана — host-side `system.toml`, который сборщик образа проверяет и
кодирует в запись. Невалидный `system.toml` ломает сборку, и композиция,
которая не поднимется на устройстве, не доходит до образа.

```toml
version = 1

[[components]]
executable = "namespace-router"
memory_limit = "8M"
restarts = 2

[[components]]
executable = "filesystem-imagefs"
memory_limit = "4M"
scope = { namespace = "/boot" }

[[components]]
executable = "filesystem-ramfs"
memory_limit = "4M"
scope = { namespace = "/tmp" }

[[components]]
executable = "files-demo"
memory_limit = "2M"
bind = { area = "filesystem-imagefs" }
scope = { area = "/files-demo" }
```

| Ключ           | Значение                                                             |
|----------------|----------------------------------------------------------------------|
| `executable`   | идентичность программы компонента                                    |
| `name`         | имя экземпляра; без ключа — идентичность программы                   |
| `memory_limit` | предел памяти компонента                                             |
| `restarts`     | число перезапусков сверх первого запуска, по умолчанию ноль          |
| `bind`         | провайдер требования `session` по имени требования                   |
| `scope`        | область требования `session` по имени требования                     |
| `instance`     | номер устройства требования `irq` либо `mmio` по имени требования    |

Ссылки на компонент идут по имени экземпляра, а не по пути программы. Композиция
поднимает одну программу несколькими экземплярами и различает их именно по
имени. Под именем экземпляра идут процесс компонента, строки его журнала и
провайдер, названный ключом `bind`. Отдельный запуск компонента называется
incarnation. Каждая incarnation получает свой процесс и свой набор capability.
Перезапуск не меняет имя экземпляра
([«Incarnation и перезапуск»](#incarnation-и-перезапуск)).

Экземпляры одной программы делят один каталог, а с ним и файлы. Ключ `path`
записи `[[programs]]` образа задаёт этот каталог
([userland.md](userland.md#образ)), и композиция не выбирает состав его файлов.

`memory_limit` — десятичное число байт с необязательным двоичным суффиксом `K`,
`M` либо `G`. Предел округляется вверх до целой страницы, и бюджет компонента не
меньше предела. Предел не преаллокация и не куча. В него засчитывается всё, что
занимает процесс.

Rootkeeper забирает у ядра capability образа, отображает его read-only и
разбирает запись плана до запуска компонентов. Отсутствие записи плана, её
порча и отсутствие программы записи — разные причины `BootFailure`, и каждая
останавливает подъём композиции целиком. Отката на вкомпилированную композицию
не предусмотрено. Состав системы задан планом целиком.

Rootkeeper не выполняет монтирований. Файловая система сама монтирует себя, и
префикс монтирования равен области её требования `namespace`
([filesystem.md](filesystem.md#монтирование)).

### Связывание

Программа компонента объявляет его требования и экспорты
([userland.md](userland.md#манифест-компонента)). Компонент получает требование
ответом rootkeeper на запрос стартовой сессии
([userland.md](userland.md#протокол-componentstartup)). Сборка сводит
объявления композиции и записывает в план провайдера и область каждого
требования `session`.

**Устройство.** Rootkeeper перебирает строки совместимости требования по порядку
и берёт первую, которую содержит описание платформы машины. Ключ `instance`
выбирает устройство среди устройств этой совместимости, по умолчанию первое.
`lib/device-resolver` находит линию и окно устройства в описании. Драйвер не
получает описания платформы.

**Сессия.** Сборка связывает требование `session` без ключа `bind` с
единственным экспортёром его протокола в композиции, а с ключом `bind` — с
названным экземпляром. Rootkeeper ставит запрос `session` импортёра в очередь
заявок экспорта провайдера. Запрос `accept` провайдера получает первую заявку
вместе с областью, и провайдер сам отвечает импортёру
([userland.md](userland.md#обслуживание-экспорта)). Заявка ждёт `accept`, а
`accept` ждёт заявки. Очередь относится к записи провайдера, а не к его
incarnation, и заявка сохраняется при перезапуске провайдера. Заявки к экспорту
записи, снятой навсегда, получают `Unavailable`.

**Область.** Ключ `scope` задаёт область требования `session`. Rootkeeper
передаёт байты области провайдеру без разбора, и смысл им даёт провайдер. Для
файловой системы область — путь, и компонент получает сессию-окно на этот
каталог ([filesystem.md](filesystem.md#сессии-окна)).

**Образ.** Каждое требование `region` получает read-only копию региона всего
userland-образа.

### Проверки сборки

Сборка сводит `system.toml` с манифестами названных им программ и отвергает
описание, которое не поднимется на устройстве. Отвергаются:

- **имена** — имя экземпляра пустое, с `/`, не-ASCII, длиннее ёмкости имени
  процесса либо повторяется у двух компонентов;
- **состав** — композиция пуста, образ не содержит названной программы либо
  имя программы без пакета совпадает у программ двух пакетов;
- **значения** — предел памяти не отвечает своей грамматике либо равен нулю;
- **экспорты** — имя протокола экспорта длиннее `PROTOCOL_ID_MAX`;
- **связывание** — протокол требования `session` не экспортирует никто либо
  экспортируют больше одного, экземпляр из ключа `bind` лежит вне композиции
  либо не экспортирует протокол требования, компонент импортирует собственный
  экспорт;
- **ключи** — `bind`, `scope` либо `instance` названы для требования вне
  манифеста, не того вида либо зарезервированного имени `log`; область `scope`
  пуста либо длиннее `SESSION_SCOPE_MAX`;
- **ёмкость** — оценка числа handle rootkeeper по составу композиции превышает
  ёмкость таблицы handle.

Сборка не проверяет циклы привязок. Запрос `session` участника цикла ждёт
`accept` провайдера, который сам ждёт ответа на свой запрос `session`. Старт
участников завершается отказом по сроку запроса
([userland.md](userland.md#старт-компонента)).

Сборка не проверяет совместимость и занятость устройств, потому что описание
платформы доступно только в рантайме
([«Провижининг устройств»](#провижининг-устройств)).

### Провижининг устройств

Rootkeeper разрешает устройство требования `irq` либо `mmio` при первом запросе
и держит полученную линию либо окно, пока работает. Каждый запрос этого
требования получает копию.

Rootkeeper отказывает в устройстве, если описание платформы не содержит
устройства, линии либо окна, если линия уже выдана другому требованию и если
окно пересекается с окном другого требования. Отказ получает только запрос
этого требования, rootkeeper пишет причину в журнал, и композиция продолжает
работу.

## Библиотека родителя

Сторона родителя протокола `ComponentStartup` — `Children` из
`lib/managed-component`. Она запускает записи, отвечает на их запросы, держит
очереди заявок `session` и запросов `accept` и отзывает выдачи ушедшей
incarnation. Rootkeeper добавляет к ней план, устройства и решение о
перезапуске.

## Incarnation и перезапуск

Перезапуск заменяет incarnation записи новым процессом с тем же именем
экземпляра. Rootkeeper закрывает свои копии выдач ушедшей incarnation, и это
отзывает всё выведенное из них в любом процессе. Новая incarnation запрашивает
требования заново. Резерв бюджета и счётчик перезапусков сохраняются при
перезапуске.

Rootkeeper перезапускает запись, если процесс вышел с ненулевым кодом либо
закрыл стартовую сессию и остался жив. Во втором случае rootkeeper сначала
завершает процесс. Число перезапусков ограничено ключом `restarts`. Запись
снимается навсегда при нулевом коде выхода, неудавшемся запуске, невозвращённом
бюджете ушедшей incarnation и исчерпанном пределе перезапусков.

Rootkeeper не делает backoff, не учитывает интервал стабильной работы и не
требует readiness-сигнала.

## Резерв бюджета

Резерв бюджета компонента создаётся до первого запуска и действует до его
уничтожения. Каждая incarnation получает весь резерв как свой ресурс. Перед
запуском rootkeeper пробно отделяет от резерва полный бюджет и сразу закрывает
пробу. Отказ пробы означает, что бюджет прежней incarnation ещё не вернулся. Резерв — капа-потомок родительского ресурса, поэтому закрытие
родительской капы отзывает его вместе со всем бюджетом компонента.

## Роли компонента

Стартовая сессия к rootkeeper — единственная capability, которую компонент
получает при входе. По ней `runtime::start_component` запрашивает журнал, а
функция `request` из `component_manifest!` — требования
([userland.md](userland.md#старт-компонента)). Компонент сам создаёт порт
каждого экспорта ([userland.md](userland.md#обслуживание-экспорта)).

Rootkeeper обслуживает один порт `ComponentStartup`. `SenderGone` значка на нём
означает уход стартовой сессии компонента. Rootkeeper пишет в журнал имя записи
с кодом выхода либо причиной ухода, после чего перезапускает запись либо снимает
её навсегда. Поток пересылки журнала работает отдельно, и его остановка
rootkeeper не завершает.

## Запись плана

Формат записи — контракт между сборщиком образа и rootkeeper; кодек находится в
`lib/userland-image`. Заголовок занимает 16 B:

| Поле            | Смещение | Размер | Описание                    |
|-----------------|----------|--------|-----------------------------|
| magic           | 0        | 8 B    | `RKPLAN\0\0`                |
| version         | 8        | u16 LE | версия формата (текущая: 1) |
| component_count | 10       | u16 LE | число компонентов (>= 1)    |
| reserved        | 12       | u32 LE | ноль                        |

За ним идут записи компонентов. Заголовок записи компонента занимает 24 B:

| Поле              | Смещение | Размер | Описание                                 |
|-------------------|----------|--------|------------------------------------------|
| restarts          | 0        | u32 LE | число перезапусков сверх первого запуска |
| executable_len    | 4        | u16 LE | длина каталога программы в байтах        |
| name_len          | 6        | u16 LE | длина имени экземпляра в байтах          |
| requirement_count | 8        | u16 LE | число требований                         |
| export_count      | 10       | u16 LE | число экспортов                          |
| reserved          | 12       | u32 LE | ноль                                     |
| memory_limit      | 16       | u64 LE | предел памяти в байтах (> 0)             |

За заголовком компонента идут байты каталога программы и имени экземпляра, затем
записи требований, затем имена экспортов в порядке объявления. Каждое имя
экспорта записано длиной `u16` LE и байтами.

Требование `session` записано видом export, потому что его источник — экспорт
провайдера. Заголовок записи требования занимает 16 B:

| Поле           | Смещение | Размер | Описание                                                           |
|----------------|----------|--------|--------------------------------------------------------------------|
| kind           | 0        | u8     | 0 region, 1 irq, 2 mmio, 3 export                                  |
| reserved       | 1        | u8     | ноль                                                               |
| name_len       | 2        | u16 LE | длина имени требования                                             |
| provider       | 4        | u16 LE | номер компонента-провайдера (export), у прочих видов ноль          |
| protocol_len   | 6        | u16 LE | длина имени протокола (export), у прочих видов ноль                |
| scope_len      | 8        | u16 LE | длина области (export), не больше `SESSION_SCOPE_MAX`              |
| instance       | 10       | u16 LE | номер устройства (irq и mmio), у прочих видов ноль                 |
| resource       | 12       | u16 LE | номер ресурса устройства (irq и mmio), у прочих видов ноль         |
| selector_count | 14       | u16 LE | число строк совместимости, не ноль у irq и mmio, ноль у прочих     |

За заголовком требования идёт имя требования, а за ним хвост по виду. У export
это байты протокола, а за ними байты области. У irq и mmio это строки
совместимости, каждая длиной `u16` LE и своими байтами. У region нет хвоста.

Провайдер требования export назван номером компонента в плане. Декодер
отвергает план кодом `requirement_provider`, если номер вне плана либо равен
номеру записи самого требования, и кодом `requirement_protocol`, если провайдер
не экспортирует названный протокол. Имя требования не повторяется в записи
одного компонента и не равно зарезервированному имени `log`: под этим именем
rootkeeper сам выдаёт журнал ([userland.md](userland.md#старт-компонента)).

Декодер самодостаточен и отвергает всё, что не отвечает этому описанию: чужую
магию, другую версию, пустую композицию, ненулевые reserved-поля, нулевой
предел памяти, значения вне объявленных наборов, пустые строки, кроме области,
и байты сверх записи.
