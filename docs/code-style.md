# Стиль кода

Документ задаёт оформление исходников: структуру файла и
дисциплину комментариев. Правила одинаковы для всех крейтов workspace; различия
между архитектурно-независимым и платформенным кодом отмечены отдельно.

## Крейт и no_std

- `#![no_std]` во всех крейтах ядра; `#![cfg_attr(not(test), no_std)]`, если
  крейт тестируется с `std`.
- `extern crate alloc` — для heap-аллокаций; `#[cfg(test)] extern crate std` —
  для тестов.
- Rust Edition 2024.
- Архитектурно-независимые крейты по умолчанию запрещают `unsafe`
  (`unsafe_code = "deny"` на уровне workspace). Платформенные крейты (`hal-*`,
  `drivers-*`) снимают запрет целиком в корне; нейтральные крейты — точечно
  на отдельном файле, и только когда без `unsafe` обойтись нельзя.

## Структура файла

Элементы файла идут в фиксированном порядке: сначала описание модуля, затем
импорты, затем определения от данных к поведению.

```rust
//! Потоковая запись байтов и блокирующая обёртка над приёмником.

use core::fmt::Write;

use crate::byte_sink::ByteSink;

/// Трейт для потоковой записи данных.
pub trait Writer { /* ... */ }

/// Обёртка над `ByteSink`, превращающая неблокирующую запись в блокирующую.
pub struct BlockingWriter<'a, S: ByteSink> { /* ... */ }

impl<S: ByteSink> Writer for BlockingWriter<'_, S> { /* ... */ }
```

Полный порядок:

1. `//!` doc-комментарий модуля;
2. crate-level атрибуты (`#![no_std]` и прочие);
3. `extern crate`;
4. `use`-импорты (группами: `core`/`alloc` -> внешние крейты -> `crate::`);
5. константы и type alias'ы;
6. определения `struct`, `enum`, `trait`;
7. `impl`-блоки;
8. свободные функции;
9. макросы;
10. `#[cfg(test)] mod tests`.

```rust
/// Записывает все байты из буфера, блокируя до завершения.
fn write_all(&self, buf: &[u8]);
```

## unsafe

Перед каждым `unsafe`-блоком обязателен комментарий `// SAFETY:`, доказывающий
корректность операции: какие предусловия выполнены и кем они гарантированы.

```rust
// SAFETY: caller гарантирует, что новый базовый адрес замаплен и хранит валидный
// объект `T` (контракт `unsafe fn`); `relocated_raw` имеет размер и layout
// `*const T`, поэтому `transmute_copy` корректно собирает fat pointer из пары usize.
unsafe { /* ... */ }
```
