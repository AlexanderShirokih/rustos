# Стиль кода

Rust-код форматируется через `cargo xtask fmt` по настройкам `rustfmt.toml`.
Правила сверх rustfmt и clippy проверяет `cargo xtask style`
([commands.md](commands.md#проверка-кодстайла)).

## Структура файла

Корень крейта содержит только `//!`-шапку, crate-level атрибуты, `extern crate`,
объявления модулей и `pub use` реэкспорты. Определения лежат в модулях. Функции
`#[proc_macro*]` остаются в корне, где их требует компилятор.

```rust
//! capability targets и таблица handle'ов.
#![cfg_attr(not(test), no_std)]

extern crate alloc;

mod api;
mod handle;
mod handle_table;

pub use handle::{Capability, HandleId};
pub use handle_table::HandleTable;
```

Файл с определениями организован в порядке:

1. `//!` doc-комментарий модуля (если он задаёт контракт сверх имени файла);
2. `use`-импорты (группами: `core`/`alloc` → внешние крейты → `crate::`);
3. константы и type alias'ы;
4. определения `struct`, `enum`, `trait`;
5. `impl`-блоки (в том же порядке, что определения);
6. свободные функции;
7. `#[cfg(test)] mod tests`.

## Именование

Сокращение допустимо там, где короткая форма стала устоявшимся обозначением
предметной области: регистры процессора (`pc`, `sp`), адресные пространства
(`va`, `pa`).

Имя константы отражает назначение или форму величины: `PAGE_SIZE`,
`BANNER_MAX_BYTES`, `REPLY_TIMEOUT`. В `BANNER_MAX` и `WAIT` не видно, что
именно ограничено.

## Язык

Комментарии и документы пишутся по-русски. Вывод программы пишется
по-английски. Сюда входят строковые литералы, сообщения паники и журнала и
`--help`, который `clap` собирает из doc-комментариев аргументов.

## Комментарии

Комментарий над тестом допустим как одна-две строки о баге,
который тест удерживает.

Документы `docs/` ссылаются на код. Комментарий на файл `docs/*.md` не
ссылается.

## unsafe

Код использует `unsafe` минимально. Разрешение `unsafe_code` ставится на модуль
или функцию, где оно нужно. Разрешение в новом коде ограничивается местом использования.

Комментарий `// SAFETY:` доказывает корректность операции: какие предусловия
выполнены и кем они гарантированы.

```rust
// SAFETY: caller гарантирует, что новый базовый адрес замаплен и хранит
// валидный объект `T` (контракт `unsafe fn`); `relocated_raw` имеет размер
// и layout `*const T`, поэтому `transmute_copy` корректно собирает fat
// pointer из пары usize.
unsafe {
    let ptr: *const T = core::mem::transmute_copy(&relocated_raw);
    &*ptr
}
```

## Обработка ошибок

Ошибки представлены enum'ом с вариантами без данных или с минимальными данными.
Каждый вариант публичного enum'а ошибок имеет doc-комментарий. `#[derive(Debug)]` — повсеместно,
`core::fmt::Display` — там, где нужен человекочитаемый вывод.

Линты `[workspace.lints.clippy]` корневого манифеста и его userspace-копии
запрещают рабочему коду панику, индексацию среза без проверки границ и
приведение, способное усечь значение, без `try_from`.

Крейт, которому линт неприменим, снимает его в своём корне. Такое снятие
получают:

- платформенные крейты — там, где запрет вытекает из природы кода;
- хостовые инструменты, которым доступна `std`;
- программы-фикстуры, у которых паника и есть способ сообщить о провале.

Остальной рабочий код снимает линт точечно у самого места.

Снятие в голове модуля допустимо там, где основание одно на весь файл. Так снят
запрет индексации в модулях, целиком собранных из `const fn`, где `get` по срезу
недоступен, и запрет дробления `unsafe`-блока в модулях, где операции блока
доказаны одним комментарием `SAFETY`. Модуль со смешанным содержимым такого
снятия не получает.
