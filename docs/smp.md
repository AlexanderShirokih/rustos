# Многопроцессорность

Планировщик работает на всех поднятых CPU. Каждый CPU имеет очередь готовых
потоков, текущий поток, idle-поток и таймер. Boot CPU инициализирует систему
и запускает остальные; после загрузки все CPU выполняют ядро с одинаковыми
полномочиями.

Syscall ABI общий для одно- и многопроцессорной конфигураций
([syscalls.md](syscalls.md)). Userspace не привязывает потоки к CPU и не
получает число CPU через ABI.

## Идентификация CPU

Аппаратное имя CPU — affinity, составленное из полей `MPIDR_EL1`.
Логическое имя — `CpuId`, индекс в таблице топологии. Таблица строится по
узлу `/cpus` описания платформы; отключённые CPU исключаются.

Boot CPU занимает индекс `0`, включая случай, когда дерево его не описывает.
Остальные идентификаторы плотные. Предел таблиц задаёт тип `CpuId`.
Разбор топологии находится в
[kernel/hal-common/src/cpu.rs](../kernel/hal-common/src/cpu.rs).

## Per-CPU состояние

Платформенный блок CPU связывает логический идентификатор с состоянием
планировщика и доступен через `TPIDR_EL1`. До установки блока регистр
обнулён. У каждого CPU свой загрузочный стек и интерфейс контроллера
прерываний.

Состояние CPU меняет его владелец либо другой CPU под общей блокировкой
планировщика. CPU без подготовленного состояния в планировании не участвует.

## Распределение потоков

Новый поток назначается наименее загруженному из работающих CPU.
Загрузка учитывает готовые и исполняемый потоки. При равной загрузке
предпочитается текущий CPU. Пробуждение возвращает поток в очередь CPU,
за которым он закреплён.

CPU без готовой работы может забрать готовый поток у загруженного CPU.
Донору остаётся работа; вместе с потоком переносится его назначение.
Выбор и перенос выполняются под общей блокировкой планировщика.

Исполняемый поток и поток, чей контекст ещё сохраняется, не мигрируют.
Их стек, IPC-буфер и адресное пространство сохраняются до освобождения
всеми CPU, даже если поток завершён извне.

При постановке работы другому CPU планировщик отправляет межпроцессорное
прерывание. Оно выводит CPU из idle или позволяет выбрать более приоритетный
поток. Отправка выполняется после освобождения блокировки планировщика.

Правила назначения и миграции реализованы в
[kernel/scheduler/src/scheduler.rs](../kernel/scheduler/src/scheduler.rs).

## Подъём вторичных CPU

Способ старта определяется описанием платформы. Поддерживаются PSCI
(`hvc` или `smc`) и `spin-table`. Способ из узла CPU имеет приоритет
над общим PSCI.

CPU запускаются последовательно. Boot CPU передаёт идентификатор, стек и
корни трансляции. Вторичный CPU включает MMU, устанавливает платформенное
состояние, настраивает прерывания и планировщик, затем сообщает о готовности
и начинает выполнять потоки.

Ожидание готовности ограничено временем. Если отказ оставляет состояние
стартующего CPU неизвестным, дальнейший подъём прекращается.
CPU, опоздавший после закрытия приёма, остаётся в idle.
Недоступная частота счётчика не позволяет ограничить ожидание и прекращает
подъём вторичных CPU.

Подъём начинается после подготовки драйверов, планировщика и начальных
потоков. Реализация и условия отказа находятся в
[kernel/hal-aarch64/src/smp](../kernel/hal-aarch64/src/smp/mod.rs).

## Прерывания и трансляция

Общая часть контроллера прерываний настраивается один раз, его интерфейс
CPU — на каждом процессоре. HAL переводит `CpuId` в аппаратный адрес
получателя межпроцессорного прерывания.

Инвалидация TLB распространяется по inner-shareable домену аппаратными
операциями и барьерами. Аллокатор ASID учитывает активный тег каждого CPU
и резервирует активные теги при смене поколения.

## Дисциплина блокировок

- Общее изменяемое состояние защищается `MutexCell`. Для `NoLockCell`
  принадлежность одному CPU должна следовать из структуры кода.
- До включения MMU спинлоки не используются. Эта фаза однопоточна;
  аллокаторы переходят к блокируемому состоянию после неё.
- Блокировка планировщика предшествует блокировке таблицы хендлов.
  Код объекта capability откладывает вызов планировщика до освобождения
  своей блокировки.
- Переключение контекста выполняется вне блокировок.
- Блокировка, доступная обработчику прерывания, захватывается с
  замаскированными IRQ. `MutexCell` сам маскирует их.
- Путь паники использует отдельный вывод с ограниченным ожиданием,
  без выделения памяти и неограниченного ожидания блокировок журнала.

## Стеки и userspace

Загрузочные стеки имеют фиксированный размер. Основной загрузочный стек
проверяется по маркеру использования; вторичные CPU получают отдельные
стеки. Защитные страницы стеков ядра не реализованы.

Потоки одного процесса могут исполняться одновременно. Совместный доступ
к памяти требует атомиков либо примитивов синхронизации
([concurrency.md](concurrency.md)).
