# IPC

IPC задаёт типизированные контракты поверх [порта](port.md).
Контракт объявляет операции, типы параметров и результатов.
Клиент и сервер используют общий формат кадров.

## Обмен

Операция `call` отправляет запрос и ждёт ответ.
Операция `cast` отправляет одностороннее сообщение; успешный возврат
подтверждает приём кадра.

Ответ содержит значение либо доменную ошибку объявленного типа.
Неизвестная операция или неверный кадр отклоняются до обработчика.
Закрытие канала ответа даёт клиенту `PeerClosed`.

Сервер различает клиентов по значку кадра. Доставка, уход сторон и тайм-ауты
определены в [port.md](port.md).

## Кадр

Кадр содержит заголовок и тело. Все целые в кадре — little-endian.
Кодирование выполняется без выделения памяти в куче.
Предел кадра — `MESSAGE_INLINE_MAX` (4064 байта), capability передаются
отдельным вектором из не более четырёх хендлов.

### Заголовок

| Смещение | Размер | Поле | Назначение |
|----------|--------|------|------------|
| 0 | 8 | `ordinal` | Идентификатор операции |

Транспорт передаёт запрос с ответом вместе с `Reply`.
Ответ направляется по этому `Reply`.

### Тело

Тело содержит записи полей и терминатор `0x00`:

```text
field_id: u8
len: u16 LE
data: [u8; len]
```

Идентификаторы полей лежат в `1..=254`, уникальны и строго возрастают.
Поле `0` завершает тело.
Получатель пропускает неизвестные поля по длине; каждое ожидаемое поле
должно присутствовать. Бюджет тела с терминатором — 4056 байт.

Параметры операции получают `field_id` по позиции, начиная с `1`.
Ответ занимает поле `1`.

### Значения

| Тип | Представление `data` |
|-----|------------------------|
| `u8..u64`, `i8..i64` | Целое little-endian размером типа |
| `bool` | Один байт: `0` или `1` |
| `&str` | UTF-8 |
| `&[u8]` | Байты |
| `Cap<K>` | Однобайтовый индекс хендла в векторе кадра |
| `Result<T, E>` | Вложенная запись: поле `1` для `T` либо поле `2` для `E` |
| `Option<T>` | Значение `T` для `Some`, пустые данные для `None` |
| `wire_enum!` | Дискриминант little-endian; тип задаётся объявлением, по умолчанию `u16` |
| Агрегат | Вложенная запись полей |

`Result` содержит ровно одно из двух полей. Их отсутствие даёт
`MissingField`, наличие обоих — `InvalidValue`.
Необъявленный дискриминант перечисления даёт `InvalidValue`.
Длина строк и байтовых срезов ограничена размером кадра. Если данные
не помещаются, кодирование возвращает `FrameOverflow`.

Вложенные записи используют общий вектор capability кадра.
Повторное использование одного индекса хендла в разных полях даёт
`InvalidValue`. Сессия протокола передаётся capability порта;
тип протокола сохраняется при компиляции.

Формат и ограничения определены в
[lib/ipc/src/wire.rs](../lib/ipc/src/wire.rs) и
[lib/ipc/src/schema.rs](../lib/ipc/src/schema.rs).

## Идентификатор операции

Каноническое имя имеет вид `<namespace>.<operation>`.
`ordinal` — последние восемь байт SHA-256 имени в UTF-8,
прочитанные как big-endian число. В заголовке это число записывается
little-endian.

| Имя | `ordinal` |
|-----|-----------|
| `Clock.now` | `0x6ca580d0d09ad48b` |
| `Calc.add` | `0xb74487cd9b2841ba` |

Алгоритм и контрольные значения находятся в
[lib/ipc/src/ordinal.rs](../lib/ipc/src/ordinal.rs).

## Запрос и ответ

Клиент кодирует параметры и вызывает операцию транспорта.
Ответ повторяет `ordinal` запроса; другой идентификатор отклоняется
с `InvalidValue`.

Сервер декодирует кадр и вызывает обработчик. Обработчик может вернуть
ответ сразу либо сохранить типизированный долг ответа.
Долг содержит одноразовый канал и идентификатор операции;
его можно передать другому процессу. Закрытие долга без ответа
завершает вызов с `PeerClosed`.

Односторонняя операция ответа не создаёт.
Запрос операции с ответом без канала `Reply` не передаётся обработчику.

Тайм-аут может наступить после приёма запроса. Он не подтверждает
отмену обработки ([port.md](port.md#тайм-ауты-и-границы)).

## Владение capability

Параметры и ответы с capability объявляются владеющими через `own`.
Отправляемый кадр удерживает владельцев хендлов; успешная доставка
переносит хендлы получателю.

Декодирование передаёт capability владельцу соответствующего поля.
Хендлы, не вошедшие в прочитанное значение, и невзятый канал ответа
закрываются вместе с кадром.

Отказ односторонней отправки или ответа возвращает `Undelivered`
с причиной и владеющим значением. Отказ кодирования и отказ вызова
закрывают владеющие параметры. Эти правила относятся к типизированной
обёртке; syscall при недоставленном переносе оставляет хендлы отправителю.

API владения и недоставленного ответа определён в
[lib/ipc/src/resources.rs](../lib/ipc/src/resources.rs) и
[lib/ipc/src/transport.rs](../lib/ipc/src/transport.rs).

## Объявление контракта

Контракт объявляется через `ipc::protocol!`:

```rust
ipc::protocol! {
    /// Часы устройства.
    pub mod clock {
        name = "Clock";

        call fn now() -> u64;
        call fn checked(value: u32) -> Result<u32, u8>;
        cast fn arm(deadline_ns: u64);
    }
}
```

Макрос создаёт клиента, серверный интерфейс и диспетчер операций.
Синтаксис и варианты объявлений заданы в
[lib/ipc/src/protocol.rs](../lib/ipc/src/protocol.rs).
Настройка срока вызовов и API клиента относятся к документации библиотеки.

## Совместимость

Каноническое имя и раскладка полей входят в ABI.
Переименование меняет `ordinal` и создаёт другую операцию.
Существующий идентификатор поля сохраняет свой тип и назначение.

Идентификаторы параметров позиционны. Удаление или перестановка параметра
может изменить раскладку последующих полей. Изменение сигнатуры должно
согласовываться на обеих сторонах; пропуск неизвестных полей не делает
произвольное изменение совместимым.
